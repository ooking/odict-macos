# ODict for Mac

轻量的原生菜单栏词典。点击菜单栏的书本图标，或使用自己录制的全局快捷键查词。

## 首版功能

- 英文单词、短语查词，输入联想（350ms 防抖）。
- 输入后到候选请求结束显示原生加载指示；候选行支持鼠标悬停高亮，悬停状态仅在该行更新。
- 多候选使用左右布局：左侧选择、右侧预览，自动选中并预览首个词；↑ / ↓ 切换并滚动到可见位置，回车确认。只有一个候选时直接显示释义，隐藏整个候选侧栏和分隔线。
- 搜索框位于顶部，产品图标、名称、设置和更多按钮位于 footer，不显示操作提示。输入法组合输入时保留其按键处理。
- 中文释义反查，英文未命中时给出近似拼写建议。
- 中英文释义、音标、词形变化、标签；释义支持选中复制。
- macOS 系统英语语音朗读。
- 自定义全局快捷键：录制、清除、自动保存及库提供的冲突提示。默认不占用快捷键。
- 选中取词：在其他应用选中单词或短语，按独立快捷键查询；读取失败时可改用截图取词，不模拟复制，不读写剪贴板。
- 悬停取词：在设置中开启后，可选择 Command、Control、Option、Shift 或不使用辅助按键，将鼠标停在单词上约 0.3 秒；优先读取鼠标处辅助功能文字，无法定位时用局部截图和本地 OCR。自动显示不抢焦点，主动点击卡片后可编辑。
- 截图取词：按独立快捷键框选图片、视频或应用中的文字，使用 Apple Vision 在本机识别后查词；Escape 取消。支持各显示器内框选，不支持跨屏拼接。
- 点击菜单栏图标打开词典，footer 中提供“选中取词”和“截图取词”图标按钮，与设置同一行，悬停显示功能名称。结果面板在取词区域附近显示，随候选栏尺寸变化保持位置锚点。
- 最近 20 条成功查词记录，支持清空。
- 独立设置窗口，可配置 HTTPS API 地址和只读 API 密钥；首次启动自动展示设置。
- Escape 收起，点击外部收起，菜单中退出。应用不显示 Dock 图标。

## 技术选择与兼容性

- 原生 Swift + SwiftUI，AppKit `NSStatusItem` / 无边框 `NSPanel` 管理菜单栏及窗口生命周期，没有弹出气泡的顶部尖角。
- macOS 26+ 使用 `NSGlassEffectView` 原生 Liquid Glass；macOS 12–15 回退到 `NSVisualEffectView` 的 `.popover` 材质。遵循系统外观，不固定背景色或强制透明度。
- 最低系统 macOS 12 Monterey；Release 使用 Xcode 标准架构（Intel / Apple Silicon）。实际兼容性仍需对应机器验证。
- Xcode 26+ / Swift 6.2+（本项目源码使用 Swift 5 语言模式，依赖使用 Swift 6.2）。
- 唯一第三方依赖：[KeyboardShortcuts](https://github.com/sindresorhus/KeyboardShortcuts)，通过 Swift Package Manager 固定为 3.1.0。使用其原生录制控件和全局热键注册。悬停开启时另用 AppKit 观察修饰键、鼠标及取消取词所需按键事件，不记录按键内容。
- `URLSession` + `async/await`；保留 Hardened Runtime。为支持跨应用 Accessibility 选中文字，关闭 App Sandbox，按 Developer ID 签名及公证的直接分发方式设计，不作为 Mac App Store 沙盒版本发布。
- 跟随系统深浅色，系统控件、系统字体，未引入网页容器。

## 在 Xcode 打开

1. 打开 `ODict.xcodeproj`，等待 Swift Package Manager 获取 KeyboardShortcuts。
2. 选择 `ODict` scheme 和 `My Mac`。若签名提示需要团队，在 Signing & Capabilities 选择自己的 Team；使用自己的 Bundle ID 分发时也在这里修改。
3. 按 Run。首次运行的设置窗口中，填入只读产品 API 密钥并保存，然后录制全局快捷键。
4. 点击菜单栏书本图标查词。没有配置密钥时，显式查询会提示打开设置。

默认 API：`https://odict-api.touchany.com`，无 `/api` 前缀。密钥在 [ODict API 管理页面](https://odict.touchany.com/admin/api-clients) 创建。不要填写管理密钥。接口契约见相邻 `odict-api/docs/product-api.md`。

### 本机 Release 构建与更新

在 Xcode 中为 Debug、Release 配置自己的 Team，并创建 Apple Development 证书后，运行：

```sh
sh scripts/build-release.sh
```

每次通过 Xcode 或脚本构建时，Build 号自动使用北京时间 `yyyyMMddHHmm`（不含秒），例如 `202610211027`；设置页显示 `1.0.1 (Build 202610211027)`。同一分钟内构建的编号相同，Version 仍在 Xcode 中手动管理。时间戳写入构建目录中的生成文件，不修改源码版本号。

脚本编译 arm64/x86_64 双架构，并使用项目的 Apple Development 开发签名；签名失败即停止，不回退临时签名。产物位于 `build/Build/Products/Release/ODict.app`。不要再使用 `CODE_SIGNING_ALLOWED=NO` 或在构建后执行 `codesign --sign -`，否则会失去稳定的开发签名身份。

更新时先完全退出 ODict，再用新产物替换 `/Applications/ODict.app`，只从该位置启动。首次从临时签名切换为开发签名可能需要重新授权辅助功能、屏幕录制或钥匙串；后续保持团队、Bundle ID 和签名类型一致，通常可保留授权。构建成功不代表已验证权限保留，测试和界面验证仍需用户同意。开发签名产物不作为 Developer ID 签名、公证的正式发行包。

设置允许指定其他 HTTPS API 地址；自定义地址应提供同样的产品 API 契约。更换地址时需同时填写新服务的密钥，保存后下一次请求生效。清空密钥并保存会从钥匙串删除密钥。

## 数据与安全

- 只读密钥保存在 macOS Keychain，不写入源码、UserDefaults 或日志。
- API 地址、快捷键、最近查词记录存于 UserDefaults；最近记录仅在本机保存，可通过菜单清空。首版没有云同步。
- 请求使用临时 URLSession，无磁盘响应缓存，不使用 Web Cookie 会话，不跟随重定向，避免把 Bearer 凭据转发给其他站点。
- 不访问剪贴板，不模拟复制，不要求输入监控或自动化权限。仅在用户触发选中取词或主动开启并触发 Control 悬停取词时读取文字；需要用户授予辅助功能权限。
- 截图取词需要屏幕录制权限，只按需获取框选区域或鼠标附近区域的单张图片，不持续录屏。图片仅在内存中用于本机 OCR，不落盘、不上传、不写日志；识别出的文字会发送至所配置词典服务，成功查词沿用最近记录规则。
- 不内置开发者共用密钥。当前是用户自带只读密钥的桌面客户端；面向公众发行时，应另行设计用户登录及服务端授权，不能把共享产品密钥打包进客户端。
- HTTP 401/403、404、429、服务错误、超时有对应提示；遵循 Retry-After 提示，不自动反复重试。

## 扩展结构

2026-10-20 流程检查后按职责拆分了应用协调、菜单栏、查词窗口、设置窗口、设置状态、输入框、HTTP 传输、限流、服务设置、最近记录及原生朗读。问题依据、模块关系、资源约束与待验证范围见 [架构检查记录](docs/architecture-review.md)。现有界面和词典接口保留，没有新增第三方依赖。

```text
ODict/App                 菜单栏、窗口、快捷键及应用生命周期
ODict/Models              词条、候选词、DictionaryServing 接口
ODict/Services            API/HTTP、服务快照、Keychain、限流、最近记录、原生朗读及取词服务
ODict/Features/Lookup     查词状态、请求取消、原生输入框、视图与查词窗口
ODict/Features/Settings   设置状态、视图、快捷键录制与独立窗口
ODict/Features/Capture    取词协调、权限/坐标/文本处理、临时框选窗口
```

界面通过 `LookupModel` 调用 `DictionaryServing`，不直接发请求。输入变化、关闭弹窗及修改服务设置时取消旧查询，并用请求标识阻止过期响应覆盖当前状态。之后可注入离线词典或测试替身。

生词本建议新增独立 `Features/Vocabulary` 和 `VocabularyRepository`，以词条 ID / 单词关联收藏、笔记和复习状态，使用 Core Data / SQLite 持久化；不要把生词数据混入最近查词 UserDefaults。维持 macOS 12 下限时不使用仅较新系统支持的 SwiftData。尚未实现生词本、离线词库或账号同步。

## 屏幕取词

2026-10-20 后续界面调整：两个取词入口最终调整为 footer 内与设置同一行的纯图标按钮，移除独立按钮行及菜单栏右键取词菜单；沿用网页版蓝色书本“O”品牌图案，添加 macOS AppIcon 资源与打包配置（16–1024 像素，含 Retina）。图标矢量源位于 `docs/design/app-icon.svg`。前一版独立按钮行及图标调整已通过 Release 双架构编译（arm64/x86_64），产物包含 AppIcon.icns 和图标元数据，并完成本地临时签名及签名校验；当前同一行纯图标布局也已通过 Release 双架构编译并完成本地临时签名及签名校验，尚未执行该布局的界面验证。用户重试后确认取词可以使用，撤回先前“无结果”反馈；此前编译和替身检查仍不能替代完整权限、跨系统、界面与内存验证。

1. 在设置中分别录制“选中取词”和“截图取词”快捷键，默认均为空；也可直接点击查词面板 footer 中设置按钮旁的两个取词图标。
2. 首次使用选中取词时申请辅助功能权限，首次使用截图取词时申请屏幕录制权限。设置页显示两项权限的状态及系统设置入口；回到应用时刷新状态。两项权限互不依赖。
3. 授权后重新触发取词；屏幕录制权限若被系统要求重启应用，按系统提示操作。拒绝权限不影响普通输入查词。
4. 识别结果直接复用现有词典查询，不提供整句翻译。空选区不查询；没有文字或超过 255 字会明确提示，不截取部分文字。结果保留可编辑搜索框，便于修正 OCR。

选中取词仅查询来源应用的焦点元素及选区边界，不扫描整个辅助功能树；安全文本控件不取词，不支持该接口的应用会提示改用截图取词。截图在 macOS 14+ 使用 ScreenCaptureKit 单次截图，macOS 12–13 回退 CoreGraphics；OCR 使用系统支持的英文及简繁中文，单边最多 4096 像素，不缓存图像。每次只保留一个有效取词任务，编辑、关闭、切换应用或显示器变化时取消旧任务，过期回调不能覆盖新结果。Escape 取消框选后返回原应用。

OCR 在所有系统上首先使用 Vision 默认修订版和默认设备调度，识别请求实际报错后，仅对本次请求尝试一次原生修订版 2 + CPU 兼容路径；取消、无文字或悬停未命中不回退，不按 macOS 版本强制降级，也不把一次故障后的降级保留到后续请求。诊断依据、语言配置、初始化延迟及验证范围见 [OCR 兼容记录](docs/ocr-compatibility.md)。没有修改系统模型、引入第三方 OCR 或增加后台预热/轮询。

默认 OCR 和兼容回退均失败时，悬停取词会在原有非激活卡片中显示“文字识别失败，兼容重试也未成功”，不抢焦点；截图取词也显示相同错误。悬停错误展示前检查当前任务、触发键与鼠标位置，已取消或过期的错误不显示；原地轻微抖动不反复请求，移走后沿用卡片收起逻辑。空白未命中、安全输入和取消仍保持安静。本次只增加最终失败提示，“识别中”中间状态尚未加入；失败卡片本次未进行界面验证。

悬停按鼠标所在部分取词：例如 `TextRecognition.frame` 在点号两侧分别取 `TextRecognition`、`frame`，停在点号上不取词；路径和下划线也作为分隔符，连字符和撇号单词保留。辅助功能与 OCR 共用源文本范围规则。2026-10-20 已用本地文本偏移和生成图片验证两侧命中、点号不命中及原有单词边界；未对真实屏幕进行此次界面复测。

退出沙盒后的首次启动只迁移旧容器中缺失的 API 地址、原有快捷键、欢迎状态及最多 20 条最近记录，保留新设置和旧容器。Keychain 的 service/account 及 Bundle ID 保持原值，不导出或复制密钥；更换开发签名仍可能需要重新授权钥匙串。

## 内存与性能原则

2026-10-20 首次点击复现：用户在启动约 4 秒后连续点击并反馈等待很久；日志显示事件派发约 1 毫秒，显示调用约 4–15 毫秒，期间进程未激活，窗口多次被收起；同时采样确认主线程处于事件等待，并非计算或钥匙串阻塞。针对这一焦点/窗口显示路径，查词窗口改用 `.nonactivatingPanel`，显式关闭 `hidesOnDeactivate`，在所有 Space 可见，并直接取得 key window 而不请求整个应用激活。外部应用切换及实际外部点击仍负责关闭，菜单栏按钮点击不再被全局鼠标监视器误判为外部点击。诊断日志补充 key-window 与当前 Space 状态。Release 双架构编译及临时签名校验通过，已更新 `/Applications/ODict.app`。用户在 10:40 重新启动后约 1.6 秒点击并确认“立即打开”；日志显示点击事件派发约 1.3 毫秒，窗口显示调用约 41 毫秒，结束时 `visible=true`、`key=true`、`onActiveSpace=true`。随后再次点击可正常收起、再次打开，点击外部可收起。本次启动首次点击的复测通过，未进行查询或修改权限/密钥；不代表已验证所有系统、Space/全屏或键盘输入场景。Apple 行为说明：[非激活面板](https://developer.apple.com/documentation/appkit/nswindow/stylemask-swift.struct/nonactivatingpanel)、[NSPanel 默认在应用失活时隐藏](https://developer.apple.com/documentation/appkit/nswindow/hidesondeactivate)。

2026-10-20 菜单栏无响应排查：对用户当前进程的调用栈采样确认，主线程停留在设置页 `onAppear → KeychainStore.read → SecItemCopyMatching`，同步钥匙串调用阻塞了界面事件处理。现改为独立串行后台队列执行钥匙串读写，设置页用异步任务加载并显示等待/重试状态，保存期间防止重复提交，查询也异步读取密钥；取消时跳过尚未执行的操作并丢弃过期结果，不额外缓存密钥。正在执行的系统钥匙串调用仍需等待系统返回，但不再占用主线程。修复已通过 Release 双架构编译及本地临时签名校验；尚未重启应用、执行启动响应回归或实际钥匙串读写测试，系统内部具体等待解锁还是授权尚未确认。

## 悬停取词

在设置的“悬停取词”分组中开启功能（默认关闭），通过“取词方式”选择 Command、Control、Option、Shift 或“不使用辅助按键”（默认 Control），并授予辅助功能权限。取词方式和开关立即生效并自动保存。可另行录制“开关热键”快速启停，与取词时按住的辅助按键相互独立；默认不开设热键。图片、扫描 PDF、视频画面及无法提供文字位置的应用还需要屏幕录制权限。按住选定的辅助按键，在单词上停留约 300ms 后触发查询；选择“不使用辅助按键”时直接停留即可。没有命中文字时不弹窗，不反复申请权限。仍使用现有 ODict 词典接口，不提供整句翻译。

- 使用系统事件监听，不轮询鼠标、不持续录屏。仅在选定辅助按键匹配时取词；额外按住其他辅助按键不会触发。输入、点击、拖动和滚动会抑制当前手势；按键模式松开并重新按住辅助按键可再次触发，无按键模式在下一次鼠标移动后重新触发。Caps Lock 不影响匹配。
- 辅助功能只访问鼠标命中元素及最多六级父元素，单次消息超时 80ms，整体读取预算 180ms（已发出的单次调用可能额外等待至其超时），最多读取附近 512 个 UTF-16 单元；通过单词边界再次核对鼠标位置，不使用模拟复制、浏览器注入或剪贴板。
- AX 无法定位时截取鼠标附近最多 640×160 点区域（边缘裁剪至当前显示器），使用已有 Vision 串行队列的同一识别流程，保留原始字符串范围，按具体单词边界命中。Retina 使用屏幕像素比例；按实际裁剪区域换算指针，避免在屏幕边缘把指针当作截图中心。空白不选最近单词，裁切边缘的词不查询。
- 自动浮窗不成为 key window，也不自动聚焦搜索框。移入卡片可继续查看；主动点击后转为可交互查词窗口。移开源单词和卡片后留出 450ms 移入宽限，Escape 或外部点击关闭。普通手动查词仍保持原焦点行为。
- 移动、松开辅助按键、快捷键、手动查询、关闭、应用/Space/显示器切换、锁屏和休眠会取消相关等待或捕获；查询沿用取消及旧响应保护。松开辅助按键后，已出现的卡片可继续读取，离开后关闭并取消查询。
- 安全输入模式及识别出的安全文本控件不取词，不回退 OCR。图片在内存识别后释放，不保存或上传；仅命中的单词发给已配置词典服务，成功结果沿用最近记录。关闭开关会移除悬停事件监听并释放 OCR 服务。

本次实现未引入第三方依赖。Release 双架构编译与本地临时签名属于构建交付；真实权限、图片识别率、全屏/副屏、焦点、事件时序与内存占用仍需单独验证。2026-10-20 经用户同意，`scripts/check-hover.sh`、`scripts/check-lookup.sh`、`scripts/check-capture.sh`、`scripts/check-runtime.sh` 四组检查均通过。新增悬停检查使用内存生成的重复单词图片实际运行本地 Vision，覆盖重复词各自定位、空白不误取、取消、连接词/撇号/重音分词、副屏及裁剪坐标、浮窗避让；其余三组覆盖原有查询、取词及运行时服务回归。未捕获真实屏幕、申请权限、读取真实密钥或调用词典服务；未发现需修复的问题，未修改生产源码。合成图片首次 OCR 期间，进程采样显示在等待系统神经引擎模型编译/初始化；300ms 仅为触发停留时间，不能作为 OCR 或查询的总延迟承诺。真实跨应用悬停、权限恢复、全屏/副屏、焦点、事件时序、识别率及内存表现尚未验证。
